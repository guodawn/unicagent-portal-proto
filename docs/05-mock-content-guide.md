# 05 - Mock 内容规范（Mock Content Guide）

> 门户是营销站，"mock 数据"即**页面文案与内容数据**。所有文案必须集中管理，禁止散落在组件 JSX 里写死长文案。
> 最后更新：2026-09-22（V0.1）

---

## 1. 内容层唯一入口：`src/mock/content.ts`

- 页面上出现的**一切文案**（导航、Hero、公告、卡片、优势、行业、LOGO、评价、页脚）都定义在 `src/mock/content.ts`，组件只负责渲染。
- 每个区块导出一个**带 TypeScript 类型**的数组/对象（如 `ANNOUNCEMENTS: Announcement[]`），类型即内容契约，研发对接 CMS/API 时可直接映射。
- PM 澄清/修改文案 = 只改 `content.ts`，不动组件。

## 2. 虚构脱敏策略（红线）

| 内容类型 | 规则 | 示例 |
|---|---|---|
| 客户名称 | 「限定词 + 行业 + 主体」结构，不得可对号入座 | 某头部车企、华东某省级电网、南方某能源集团 |
| 评价署名 | 虚构职务 + 脱敏企业 | 某大型制造集团 · CIO |
| 指标数字 | 允许模拟，但须为合理量级，不得宣称真实性 | "闲置资源利用率提升 35%" |
| 联系方式 | 占位域名/地址，页脚标注原型 | contact@unicagent.example |
| 备案/资质 | 不使用真实备案号，底条标注原型演示 | — |

## 3. 文案风格基调

- **B 端科技调性**：克制、具体、有数字；避免"赋能""抓手"类空话堆叠。
- 标题公式：`能力/价值 + 场景`（如"低代码智能体编排，业务人员两周上线"）。
- 每个卡片描述 2–3 行（≤ 60 字），副标题（lead）1 行（≤ 40 字）。
- 按钮：动词开头（立即体验 / 了解详情 / 查看方案 / 联系我们），长度 ≤ 4 字。

## 4. 与路由的对应

内容对象中所有跳转一律使用**路由路径字符串**（如 `/agent-platform/workbench`），并在 `03-information-architecture.md` 的路由表中登记；新页面必须先登记路由再写内容。

## 5. 后续扩展

- 大模型广场 V0.2 将增加 `mock/models.ts`（模型清单 + 报价 + 能力标签），供清单页与详情抽屉使用；
- 届时延续本规范：类型定义 + 虚构模型数据 + 集中管理。
